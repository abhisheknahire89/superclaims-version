1. WHAT THIS PROJECT IS
-----------------------
Two layers, kept separate:

A) COMPETITOR RESEARCH on Superclaims (https://superclaims.ai/).
   - Indian health-insurance claims-adjudication AI.
   - Files: 01-competitor-evidence.md, source-ledger.csv (64 evidence rows), raw/.

B) OUR PROPOSED PRODUCT, working name "Adjudication Workbench (AW)".
   - A review assistant for Indian insurers and TPAs.
   - Files: docs 02–12 plus machine-readable contracts (schemas/, config/, api/, db/, fixtures/, verification/).
   - A working Phase 1 codebase in workbench/.

AW in one paragraph:
   - It turns a claim's document bundle (claim form, discharge summary, itemised bill, pharmacy and investigation bills, receipts) into evidence-linked facts.
   - It runs the customer's own configured rules deterministically to recommend a payable amount, with line-level deductions and the clause that authorises each one.
   - It flags clinical and anomaly questions for the right human, and drafts queries.
   - A human ALWAYS makes the decision.
   - First slice: IPD reimbursement, one product config, one network tariff, English documents.

  The extraction pipeline enforces this too: it detects injected instructions and ignores them.
- Never claim that a skill was installed, a browser session inspected, or a test run unless it actually happened.

- The user has ChatGPT Plus. The earlier work was done by Claude in a cloud session.

Product principles (02-PRD §3; enforced in code and DB):
 1. Human authority.
    - The engine outputs a RECOMMENDATION and never records a disposition.
    - There is no "Reject" output. The strongest negative is REFER_CRC.
    - Only the insurer's Claims Review Committee (CRC) can repudiate.
    - A TPA tenant only records the insurer's outcome (communicated_by=INSURER) and produces no letter or worksheet.
 2. Deterministic money.
    - Decimal arithmetic in the engine; paise BIGINT in the DB; strings like "107591.00" in the API.
    - Models never compute amounts.
 3. Evidence or nothing.
    - Every fact, finding and deduction links to a document, page, bbox and quote.
    - Every deduction carries `authority` = {artifact@version, doc_id, clause}.
    - A rule that would deduct without a clause reference raises ConfigurationError, and the evaluation FAILS. The DB also rejects such adjustments.
 4. Abstain when uncertain. Identity, date or itemisation conflicts BLOCK the scopes they affect. They become queries or review tasks, never guesses.
 5. Customer-authored rules.
    - Configs are versioned and effective-dated, with four-eyes publish (author ≠ approver, DB check).
    - They are selected by admission date, never "latest".
 6. Clinical humility. Clinical and anomaly outputs are questions, with an uncertainty note. An anomaly is never called fraud.
 7. Regulatory clocks are first-class (TAT shown per claim).

5. THE ENGINE AND THE WORKED TRACES (06)
----------------------------------------
Default calculation order (illustrative; the order is product configuration, OQ-22):
  Gates        R-GATE-IDENTITY → R-GATE-DATES → R-GATE-ITEMISATION → R-GATE-LINE-CATEGORY (workbench only)
  Eligibility  R-ELIG-POLICY-ACTIVE → R-ELIG-WAITING        (findings only, never deductions)
  Line rules   R-LINE-DUPLICATE → R-LINE-NONPAYABLE → R-LINE-TARIFF → R-LINE-ROOM-CAP → R-LINE-PROPORTIONATE
  Claim rules  R-CLAIM-SUBLIMIT → R-CLAIM-DEDUCTIBLE → R-CLAIM-COPAY → R-CLAIM-SI-CAP → R-CLAIM-ROUNDING
  Anomaly      R-ANOM-* (flags only; R-ANOM-BILLNO-REUSE 0.9.0 implemented)
Catalogue-only rules (not implemented):
  R-ELIG-EXCLUSION, R-ELIG-PREPOST-WINDOW, R-LINE-PACKAGE, R-LINE-IMPLANT-INVOICE,
  R-ANOM-DUP-CLAIM, R-ANOM-LOS-OUTLIER, R-TAT-CLOCK, R-CLIN-SUMMARY

Semantics:
- Each bill line has `remaining`. Rules act only on `remaining`; a fully disallowed line is skipped by later rules.
- At most one adjustment per (evaluation, line, rule).
- Claim rules apply to the running admissible amount.

Reviewer overrides:
- Keyed by (line, rule), with a line_fingerprint.
- If the line changes on re-evaluation, the engine amount applies again and an OVERRIDE_NEEDS_RECONFIRMATION finding is raised.

Recommendation types:
  REFER_CRC > QUERY_AND_REFER_MEDICAL > QUERY > REFER_MEDICAL > INVESTIGATE > PAY_FULL > PAY_PARTIAL
  human_decision_required is always true.

Trace results (the engine must reproduce these exactly):
  trace 1   PAY_PARTIAL   billed 1,09,360.50 → payable 1,07,591.00 (includes −₹0.50 rounding)
  trace 2   PAY_PARTIAL   billed 1,72,455.75 → payable 85,000.00 (SI cap binds)
            Co-pay before SI cap matters: reversing the order gives ₹76,500 (an ₹8,500 swing).
  trace 2b  reviewer override of the L14 tariff deduction to 0: admissible 1,02,385.75, payable still 85,000.00
  trace 3a  QUERY_AND_REFER_MEDICAL, no payable
            Blocked: ALL_FINANCIAL, LINE_RULES, PRE_POST_WINDOW, ROOM_DAYS, WAITING_PERIOD.
            Findings:
              - identity conflict (bill says "Mr. Sunil Sharma", M; member is Sunita Sharma, F);
              - date conflict (02-09 vs 03-09);
              - summary bill only (no itemisation);
              - possible PED within waiting period (medical officer question);
              - bill-number reuse anomaly (SH/26/0915 also on CLM-DEMO-0088).
  trace 3b  REFER_MEDICAL, payable 85,570.00, after:
              - the corrected itemised bill and the admission record arrive;
              - the date conflict is resolved to 2026-09-02.


6. THE WORKBENCH CODEBASE (workbench/)
--------------------------------------
Stack (see workbench/docs/ADR-12 for why it differs from ADR-01/02/04/09/10):
- Language: Python ≥3.11 (tested on 3.13.16).
- Web: Starlette 1.6.0 + uvicorn 0.53.0, instead of FastAPI.
- Validation: jsonschema 4.26 + referencing 0.37.
- PDFs: pdfplumber 0.11.10 (text and word boxes); pypdfium2 5.13 (page PNG at 110 dpi); reportlab 5.0.1 (synthetic PDFs and worksheet PDF).
- Database: PostgreSQL 16 via aw/db/pgwire.py, a stdlib wire client (SCRAM, extended protocol).
  psycopg 3 is used automatically if installed — that path is UNTESTED.
- UI: plain ES-module JavaScript, no build step, no third-party code.
- Auth: development HMAC tokens (OIDC not built).
- Storage: local write-once store (S3 Object Lock adapter is a stub).

Pipeline:
  upload → ingest (sniff MIME, quarantine, dedupe by sha256, render pages)
    → EXTRACT job (classify, extract, validate against the schema, ground each quote, detect injection)
    → RECONCILE job (resolve facts, sync bill lines, categorise via the classifier map)
    → EVALUATE job (engine) → reviewer actions → decision → EXPORT job

Job queue:
- A Postgres table using SELECT … FOR UPDATE SKIP LOCKED with leases and backoff.
- Run as role aw_worker. Only error codes are stored, never PHI.

API conventions (contract-driven):
- Idempotency-Key is required on POSTs where the contract says so (400 if missing).
  A replay returns the stored response with header Idempotent-Replay: true. Reusing a key with a different body → 409.
- ETag is "rv-<row_version>". If-Match is required on claim-mutating calls (428 if missing, 412 if stale).
  The idempotency check runs BEFORE the If-Match check.
- Errors are RFC 9457 problem+json, e.g. type .../second-approval-required (409, with "triggers"), si-exhausted, validation-failed (422).
- Signed URLs: HMAC over path|tenant|exp, 300 s.
- Operations (33 paths, 36 ops):
    - me and claims: getMe, createClaim, listClaims, getClaim, assignClaim, withdrawClaim, reopenClaim;
    - documents: createDocumentUpload, listDocuments, completeDocumentUpload, getPage;
    - evaluations: requestEvaluation, getCurrentEvaluation, getEvaluation, diffEvaluations;
    - review: recordReviewerAction, listFacts, listBillLines, listFindings;
    - queries: draftQuery, approveQuery;
    - decisions: recordDecision, requestApproval, approveRequest, returnRequest, getWorksheet;
    - audit and exports: listAuditEvents, listExports;
    - configs: listConfigArtifacts, createConfigDraft, validateConfig, replayConfig, publishConfig;
    - imports and integrations: importPolicies, importSiLedger, receiveTmsEvent.

12. GOTCHAS LEARNED DURING THE BUILD
------------------------------------
- Root and clusters:
  - When running as root, dev_db.sh and the tests run initdb/pg_ctl via `su postgres`.
  - Clusters must live under /tmp, because the postgres user cannot read other directories.
- Don't `pkill -f aw.server` from a shell whose own command line contains "aw.server" — it kills itself. Use a pid file.
- UI tests: after clicking a sign-in button, wait for #who to update before navigating. login() sets location.hash and can race with a navigation.
- Supervisors and medical officers also see the "Add a document" form. Scope UI selectors to [role=tabpanel].
- Evidence selection must reset when switching claims; this was a bug and is now fixed in showClaim.
- Idempotency must be checked before If-Match, or a replay returns 412.
- Loading the harness module by path: register sys.modules[spec.name] before exec_module, or dataclasses fails.
- unittest collects module-level aliases of TestCase classes twice. Use base classes, not `_cls = Foo`.
- Browser 4xx responses also log "Failed to load resource" console errors. ui_smoke.py ignores those and judges by HTTP status; the expected 409 on the second-approval path is allowed.
- verification/check_refs.py fails the build if any doc cites an ID (ADJ-…, EVAL-…, etc.) that no fixture contains.
