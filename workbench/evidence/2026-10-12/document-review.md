# Independent agent review — Milestone 1 document reading

12 October 2026. Scope: local OCR/image/PDF ingestion, ZIP validation, extraction grounding, manual confirmation, financial gates, document API and reviewer UI. This is an independent agent code review, not a human external security audit. No credentials/.env were read; no hosted application services were called; implementation was not modified by this reviewer. Findings describe the reviewed working tree before remediation.

## Executed evidence

`cd workbench && AW_ENV=test AW_REQUIRE_DB=1 PYTHONPATH=src:tests .venv/bin/python -m unittest tests.test_document_reading -v`: **9 passed, 0 failed/skipped**, 2.418 seconds. Full suite, browser and destructive resource-exhaustion trials: **NOT RUN by reviewer** (parent owns milestone verification). Safe pure-function probes below were executed.

## Actionable findings

1. **P1 — stacked OCR values inherit label confidence and bypass money gate.** `extraction/providers.py`, `_logical_fields`, lines 112–124: merged line keeps `{**ln}` confidence from label only. Executed probe: `Grand Total:` confidence .99 followed by `1234.50` confidence .40 produced `bill.total` confidence **.99** and quote `Grand Total:\n1234.50`. `evaluations.py` only blocks facts below .95. Set merged confidence to minimum of every source line/word, preserve union geometry including x0, and test both colon and standalone label formats through evaluation; payable must remain absent until human confirmation.

2. **P1 — request body/staging resource limits apply too late.** `api/claims.py:172–179` buffers arbitrary PUT body and writes it before checking the slot's declared size or 50 MB maximum. Hash/size checks happen only on `:complete`. A signed upload holder can consume memory/disk without completing a document; write-once staging then prevents corrected replacement. Stream with a hard byte limit and slot size limit before persistence; reject mismatched sizes and expired/missing slots, and test oversized body without leaving stored bytes. Generic JSON routes also buffer unbounded bodies in `api/core.py:150–151`.

3. **P1 — PDF page count/raster dimensions are unbounded before allocation.** `extraction/pages.py:37–47,58–59` processes every page and renders at 220 DPI before OCR's 40M-pixel check. Small compressed PDF files can request enormous MediaBox raster allocations or many pages; 50 MB byte limit and ZIP expansion checks do not bound rendered work. Validate PDF page count and dimensions before rendering, enforce total rendered-pixel/page budgets and execution limits, and map rejection to a stable 422 error. A destructive allocation probe was deliberately not run.

4. **P1 — an unreadable page inside a readable document does not block money.** Provider skips `text_layer=NONE` pages with `LOW_LEGIBILITY`; pipeline completeness only counts required paths and existing lines and ignores this warning. `evaluations.py` gates only whole-document failed statuses/missing fields/low confidence facts. Executed two-page probe confirms missing page produces only `LOW_LEGIBILITY` and no facts on page 2. A bill with reconciled readable-page totals and unreadable continuation can become review-ready without acknowledging missing evidence. Require page-level readability acknowledgement or legible replacement before financial calculation for material document types; test valid bill plus unreadable continuation, not just wholly unreadable PDFs.

5. **P2 — manual entry cannot repair OCR omissions or empty OCR.** `extraction/manual.py:26–31` requires quote already present in machine page text and lines; UI `app.js:606–608` requires the same literal OCR line. A human cannot enter visually legible handwriting/OCR-missed text from the immutable source image. This falls short of full manual entry without a model. Add append-only human transcription tied to page/image digest and bounded geometry, with explicit human confirmation/provenance; do not relabel it as machine-verified text. Keep financial abstention until the appropriate human review is recorded. Test a source image with deliberately empty/incorrect OCR text.

6. **P2 — malformed ZIPs escape the API error mapping.** `api/claims.py:199` catches only `(ValueError, OSError)`. Executed probe confirms `zipfile.BadZipFile` is neither; corrupt central directories/CRC and unsupported compression can escape as 500 after sniffing the PK header. Catch expected archive/parser failures explicitly, return safe 422 codes, and test corrupt ZIP, bad CRC, unsupported method, symlink, encrypted member and expansion-limit boundaries.

7. **P2 — automated grounding verifies quote occurrence only.** `extraction/pipeline.py` validates schema then calls `grounding.check(quote,page_text)`; it does not verify the field value is derivable or bbox lies on the source geometry. Manual path now does these checks, automatic path does not. Local fixture provider remains selectable and can supply schema-valid invented values with a true unrelated quote. Add shared grounding/value derivability/geometry validation for both paths, including every evidence span; test real quote plus altered total/date, nonexistent/out-of-bounds bbox. Hosted provider is rejected by current context, which is good, but trusting provider output remains unsafe.

## Positive observations and limits

ZIP validation is in memory and does not extract member paths; it rejects traversal, duplicate names, symlinks, encryption, unsupported file signatures and declares count/expansion limits. OCR uses a local subprocess with a per-page 60 second timeout; source images are preserved and deskew boxes are mapped back. Manual document lookup includes tenant, claim and document identifiers; API page metadata checks ownership and signed assets are bound to the full URL path. Reviewer fact correction restricts selected facts to the same claim/path/value. These are code observations, not exhaustive penetration-test claims. Existing targeted tests passed but do not cover the defects above.
