# ADR-17 — Secure local platform

Accepted12October2026. Password authentication uses per-user salted scrypt hashes and DB-backed opaque sessions (only token hashes persisted),8hour expiry, revocation, five-attempt15minute lockout and CSRF checks on cookie-authenticated mutations. Session cookies are HttpOnly/SameSiteStrict and Secure for HTTPS/production; loopback HTTP development omits Secure so native startup works. Roles/limits are reloaded on each request. Development HMAC bearer authentication is accepted only in the test environment. No hosted IdP is contacted; OIDC remains an unconfigured interface. The synthetic seed password is public for this explicitly synthetic local demonstration, and is not a production credential.

Workers hold their job row lock across the handler transaction and atomically mark success with domain writes. Lease ownership/attempt fencing prevents stale completions, expiry is reclaimable after a crashed transaction, and attempts are bounded. Retry messages/logs contain identifiers and error codes only. No exception text or tracebacks are emitted into application logs; HTTP access logging is disabled. Application logs are structured JSON.

Local objects use atomic exclusive hard-link publication from unique temporary files, checksum verification and read-only permissions. They resist concurrent application overwrite; they are not compliance WORM storage against the host administrator. Audit anchors copy each verified chain head into append-only tenant rows and local immutable objects through scheduled jobs. A host administrator who controls both DB and files can replace both: no external trust anchor or regulatory tamper-proof claim is made. Deadline alerts stay inside AW and never dispose a claim.

Backup captures a PostgreSQL custom dump and local objects with a hash manifest. Restore verifies the manifest and restores into a newly named database/object directory only; existing targets are refused. The actual drill is recorded in m4-backup.log and m4-restore.log, including restored counts and per-claim chain verification. Docker remains not run because its daemon is unavailable. No external storage, email or insurer integration is added.
