# ADR-19 — Authorization and recovery defects found during final verification

Accepted 13 October 2026. Independent probes found four application defects and one inherited receiver authorization defect. Second approval now fails closed when the named supervisor has no approval limit; local user management cannot imply unlimited money authority. Draft and approval of queries reject closed claims. Idempotency hashes bind the actor and the current DB-backed roles/limit: same-authority retry returns the original result, while cross-user keys and revoked authority return a conflict without cached claim data. This retains tenant-wide key uniqueness and does not create bearer-like keys.

Restore requires exact manifest/file-set equality, the custom dump entry and version, rejects symlinks, verifies every listed hash, then verifies all restored original hashes against the DB plus referenced page assets, local exports, anchors and audit chains. A restore that fails after DB creation leaves the newly named target for diagnosis; it never overwrites a target. A manifest and dump both maliciously rewritten by a host administrator remain outside local tamper-evidence guarantees.

The user requires existing integration endpoints unchanged and no new integration. Their routes, schemas and handlers remain unchanged. The inherited TMS receiver nevertheless allowed a READ_ONLY user to withdraw a claim. A security-only guard in the shared platform request layer now requires supervisor withdrawal permission before the inherited receiver executes. Leaving a delivered authorization bypass would conflict with the role-matrix/RLS security requirements. This resolution adds no adapter, keys, webhook, delivery or external call; the integration remains not built. test_inherited_receiver_platform_rbac proves read-only/config/processor mutation is forbidden.

The browser exposed a document taxonomy mismatch: an engine query requests FINAL_BILL_CORRECTED, a semantic request rather than a new upload type. The composer requests the existing FINAL_BILL_ITEMISED type and preserves the wording asking for a corrected bill. A route parity test now checks every declared operation both directions with the contract's /v1 server prefix. New local paths follow that existing convention. A late claim refresh cannot overwrite a new queue/dashboard route; claim data is assigned only after a navigation/sequence check.

Named proof: test_hardening TC-REV-01, TC-SEC-02, TC-REL-04 actually SIGKILLs a worker after evaluation writes and before commit, verifies rollback, expires the lease and verifies exactly one recovered evaluation/audit chain; draft-letter TC-QRY-01 is in test_operations. Browser TC-UX-02 and final proof logs are linked from the delivery report.

Final recovery check also simulates a crash between publishing immutable bytes and their checksum. Identical-byte re-put may atomically create the missing checksum; different bytes or a mismatching existing checksum remain forbidden. Both data and checksum use exclusive hard links, avoiding partial checksum publication. `test_interrupted_object_publication_recovers_identical_bytes_only` proves recovery and corruption refusal. Restore database handles now close through `contextlib.closing` on exceptional verification as well as success; failed new targets remain intentionally available for diagnosis.

Final full-log inspection found the contract mutation runner copied the entire repository including a live PostgreSQL socket. Its failure was masked by an `&&` command despite `set -e`. The runner now copies only normative validator directories, excluding application runtime/secrets, and the shell executes it as a required standalone gate. Final original and clean-checkout packs each caught all eight mutations and exited successfully. Earlier pack exit0 claims do not prove that failed mutation gate passed.
