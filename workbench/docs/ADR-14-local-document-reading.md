# ADR-14 — Local document reading and human confirmation

Accepted 12 October 2026. The assignment requires no hosted application services, superseding managed OCR/model assumptions in 07 and ADR-12. Native pdfplumber reading falls back to local Tesseract for scanned pages and images. OpenCV deskews and denoises temporary OCR input; source bytes stay write-once and OCR boxes map to original coordinates. ZIPs are validated in memory before ingestion with path, symlink, encryption, member-count and expansion limits.

Critical confidence below .95 blocks financial calculation even where another source agrees. Manual readings create a new extraction version, validate schema, source quote, bounding box and value derivability, and reprocess; they do not overwrite the source or original facts. Existing fact correction now requires a grounded observed value. The API gains a contract-declared reading-confirmation operation. A conservative trailing-column fallback handles unfamiliar tables; uncertain columns still require a reviewer. Handwriting and arbitrary layouts are not claimed solved.

Evidence: test_document_reading exercises native text, JPG/PNG OCR, scanned PDF OCR, ZIP validation, financial abstention and append-only grounded manual confirmation. Training metrics and independently generated reserved layout metrics are synthetic benchmarks only; missing/incorrect readings require manual correction. No optional model was downloaded.

OCR omissions require an explicit visual transcription attestation tied to the immutable page-image hash, selected bounding box and acting reviewer. These quotes are stored append-only under tenant RLS and marked HUMAN_TRANSCRIPTION on every subsequent use. They are human readings, not machine-verified source text. Unreadable pages continue blocking money until a reviewer explicitly reviews the full page for critical conflicts; ordinary field entry does not clear that gate. Automatic extraction cannot invent a human attestation. Tests cover image hash mismatch, repeated-use provenance, full-page review, append-only enforcement and cross-tenant invisibility.

Spec/test conflict: the historical hallucinated-total test expected a payable computed from bill lines despite no grounded stated bill total. The assignment requires abstention on missing critical money fields. The test now retains its NOT_FOUND/no-resolved-total assertions and additionally requires no payable plus ALL_FINANCIAL blocking. This strengthens safety rather than hiding a failed validation. All five historical valid-money traces remain unchanged.
